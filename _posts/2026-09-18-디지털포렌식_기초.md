# 디지털 포렌식 기초 : 안티 포렌식부터 파일 카빙까지

- 안티 포렌식이란?
    - 디지털 정보를 분석하지 못하도록 삭제하는 기술
        - 보통 범죄자들이 자신들의 범행을 숨기기 위해 많이 쓴다고 함
        - 데이터 파괴
            - 사용 흔적을 없앨 수 있는 모든 기법을 말한다
        - 데이터 암호화
            - 외부 유출로 부터 지키기 위해 사용하는 기법
            - 중요 데이터를 보호하기 위해 사용됨
        - 데이터 은닉
            - 스테가노그래피 등
            - 데이터를 어딘가로 숨기는 기법으로 쉽게 찾지 못하게 할 때 사용된다
        - 데이터 난독화
            - 이는 여러 난독화 기술 중 ‘데이터’키워드 하나일 뿐이다.
            - 실행 가능한 코드를 수정해 이해, 해석, 실행에 사용할 수 없도록 하는 것이다
        - https://www.appsealing.com/kr/코드-난독화/
        - 데이터 변조
            - 파일 시스템의 시간 정보를 조작하는 것이 가장 흔하다
            - 
        - 풋프린트 최소화
        - 분석 시간 증가
    - 안티 포렌식 목적
        - 증거 탐지 회피
        - 정보 수집 방해
        - 포렌식 수사관의 분석 시간 증가
        - 디포 도구 작동의 오류
        - 로깅 차단 우회 혹은 삭제
        - 법정 보고서나 증언으로서의 가치 훼손
        - 데이터 피난은 찾아보니 없다고 뜸… 데이터를 어딘가로 피신시키는 건가..?

문제점

1. 조사해야 할 디지털 증거물의 양이 증가하고 있다
2. 운영체제, 파일 형식이 다변화 되고 있다
3. 이 과정에 많은 노력과 인력이 들어간다
4. 조사 역량이 따라가지 못한다
5. 결과 중심적이므로 결국 유효한 결과가 아닐 시 고객에게 무용지물의 수사가 된다

YTN 사이언스에서 디지털 포렌식 관련 영상을 얼마 전에 올렸더라구요!

- 이메일, 메신저, CCTV, 네비게이션 까지 누군가의 행동, 위치를 밝힐 수 있어 디포 수사의 활용이 넓어지고 있음
- 사생활 침해에 따른 개인정보 보호 문제
    - 직업 윤리에 대해 생각해 볼 필요가 있음

경찰의 디지털 포렌식 실태와 개선방안

1. 디지털 포렌식 전문인력은 부족하며, 디지털증거 분석은 해마다 증가하고 있다. 특히 디지털 포렌식 전문인력의 지역별 불균형은 심각한 것으로 나타났다.
2. 디지털 포렌식 교육대상 인원이 일선 수사경찰관 수에 비해 부족하다.
3. 경찰의 디지털증거 분석장비는 노후되었으며, 보급된 디지털 포렌식 장비도 부족하다.
4. 디지털 포렌식의 중요성에 비해 일선 수사경찰관의 전문성이 문제가 발생하고 있다
5. 경찰에서 이뤄지는 디지털 포렌식 연구활동은 없는 것으로 나타났다. 

문제점 해결

1. 경찰의 디지털 포렌식 조직체계를 강화해야 한다
2. 경찰청의 사이버테러대응센터 디지털증거분석팀의 경우 그 규모와 인력을 확대하여 디지털증거분석과의 수준으로 격상하여 디지털 포렌식에 있어서 수사와 분석 그리고 지원에 있어 종합적인 대응체제를 구축하여야 한다
3. 지방경찰청의 사이버수사대 디지털증거분석실은 현재 경찰청 사이버테러대응센터 디지털증거분석팀의 수준으로 만들어 디지털증거와 디지털 포렌식에 대한 효율적인 대응체제를 구축하여야 한다
4. 전문적인 기술과 능력을 갖춘 전문인력의 확충이 강화된 디지털 포렌식 조직에 필요하다
5. 경찰인력도 그에 맞는 기술과 능력을 갖춘 전문인력을 채용해야 한다.

특징

1. 정당성의 원칙
    1. 디지털 자료 증거가 적법한 절차를 거쳐 수집되었는가
    2. 위법한 방법으로 수집된 증거는 법적 효력성을 상실한다
2. 재현의 원칙
    1. 피헤 당시와 동일한 조건에서 현장 검증시 동일한 결과가 도출되어야 한다
3. 신속성의 원칙
    1. 컴퓨터의 휘발성 정보는 신속한 조치에 의해 결전되어야 한다
    2. 신속히 수행할 것
4. 연계 보관성의 원칙
    1. 디지털 증거물 획득
    2. 이송
    3. 분석
    4. 보관
    5. 등 법적 제출의 각 단계에 따른 책임자를 명시해야 한다
5. 무결성의 원칙
    1. 획득한 디지털 증거가 위조 또는 변조되지 않았음을 증명해야 한다

유형

1. 데이터 포렌식
    1. 디스크 파일 시스템 분석
    2. 디스크 검색
    3. 복구
    4. MAC 분석
    5. 키워드 검색
    6. FAT, NTFS, EXT2, EXT3 등을 쓸 수 있다
2. 네트워크 포렌식
    1. 네트워크를 통한 데이터, 로그 분석
    2. 라우터, 스위치,FW,IDS
3. 데이터베이스 포렌식
    1. 데이터베이스로부터 데이터를 추출, 분석
    2. 기업의 분식회계, 횡령, 탈세수사시 필수다
4. 모바일 포렌식
    1. 휴대용 기기에서 필요한 정보를 수집, 분석
    2. 휴대용 기기의 은닉 용이성으로 세심한 분석이 필요하다
5. 회계 포렌식
    1. 저장된 회계 데이터를 추출하고 회계 전문가가 분석할 수 있도록 데이터를 정제
    2. 기업의 부정 등과 같은 수사에서 필수적으로 필요하다

    1. 웹 서버와 통신을 하며 클라이언트에 생성된 흔적이다
    2. 대부분 웹 브라우저 로그이다

    1. 원본 저장매체의 변조를 방지하기 위해 별도의 매체에 블록 단위로 복제하는 작업이다
6. 라이브리스판스
    1. 휘발성 정보를 신속하게 수집하기 위해 대상 시스템의 전원이 켜진 상태로 정보를 수집하는 기법

디지털 증거의 특징

1. 비가시성, 비가독성
    1. 0과 1의 비가시적인 디지털 형대로 이루어진 증거
    2. 육안으로 식별이 불가능하다
2. 변조 가능성
    1. 오류에 의한 손상이나 의도적인 삭제 및 변조가 가능하며, 이 사실의 발견이 어렵다
3. 복제 용이성
    1. 원본과 동일한 복제본 생성이 가능하고 구분이 어렵다
    2. ex) 복사 붙여넣기 처럼
4. 전문성
5. 휘발성
    1. 전원이 꺼지면 없어지는 디지털 증거의 특징이다
6. 네트워크 관련
    1. 특정 지점에만 존재하는 것이 아니라 각종 네트워크를 통해 연결된다. 
7. 매체 독립성
    1. 디지털 증거는 유체물이 아닌 각종 디지털 저장매체에 저장되어 있거나 네트워크를 통하여 전송 중인 정보 그 자체이다. 
    2. 디지털 증거는 원본과 사본의 구별이 불가능하다

디지털 포렌식 5대 원칙

1. 정당성의 원칙
    1. 획득한 증거 자료가 적법한 절차를 준수해야 하며, 위법한 방법으로 수집된 증거는 법적 효력을 상실한다
2. 무결성의 원칙
    1. 수집 증거가 위조 및 변조 되지 않았음을 증명할 수 있어야 한다
3. 재현의 원칙
    1. 피해 직전과 같은 조건에서 현장 검증을 실시하거나 재판이나 법정의 검증 과정 에서도 동일한 결과가 나와야 한다
4. 신속성의 원칙
    1. 휘발성 증거의 수집 여부는 신속한 조치에 의해 결정되므로 모든 과정은 지체 없이 진행되어야 한다
5. 절차 연속성의 원칙
    1. 증거물 획득 → 이송 → 분석 → 보관 → 법정 제출의 각 단계에서 담당자 및 책임자를 명확하게 해야한다
    2. 수집된 저장 매체가 이동 단계에서 물리적 손상이 발생했다면 이동 담당자는 이를 확인하고 해당 내용을 정확히 인수 인계하여 이후의 단계에서 적절한 조치가 취해지도록 해야한다

수사 원리와 복구 범위

1. 사용자의 ID, PW, 파일이 만들어지고 마지막으로 접근된 타임라인의 분석, 삭제된 파일의 복구, 이미 삭제된 파일의 존재 여부까지 확인이 가능함
2. 아이폰 7 이후, 갤럭시 s10 모델부터 보안 기능이 강화되어 포렌식을 통한 데이터 복구가 어렵다.
3. 데이터를 한번 지우고 새로운 데이터가 덮어 쓰여졌다면 증거가 수집되지 않을 가능성이 높다.

제 4조 (디지털 증거의 무결성 유지)

: 디지털 증거는 그 수집 및 분석 과정에서 이용된 도구와 방법의 신뢰성이 유지되어야 한다. 

제 5조 (디지털 증거의 신뢰성 유지)

: 디지털 증거는 그 수집 및 분석 과정에서 이용된 도구와 방법의 신뢰성이 유지되어야 한다. 

제 6조 (디지털 포렌식 수사관의 임명)

1. 디지털 포렌식 수사관은 다음 각 제 1호 또는 제 2호에 해당하고 제 3호의 자격을 갖춘 수사관 중에 대검찰청 과학수사부장의 제청으로 검찰총장이 임명한다. 

1. 대검찰청 디지털 수사과에서 실시하는 ‘디지털 포렌식 전문가 양성과정’의 교육을 이수한 자
2. 국내, 외 컴퓨터 관련 교육 과정을 이수한 자로서 디지털 포렌식 관련 지식이 충분하다고 인정되는 자
3. 3개월 이상 디지털 포렌식 수사 실무를 수행한 경력이 있는 자
    1. 디지털 포렌식 수사관으로 임명된 자는 전문성 향상을 위하여 매년 대검찰청 디지털수사과나 국내외 국가기관, 전문교육기관 또는 학회에서 실시하는 디지털 포렌식 관련 교육을 이수하여야 한다. 

제 12조 (과잉금지원칙 준수)

: 디지털 증거를 압수, 수색, 검증할 때에는 수사에 필요한 최소한의 범위에서 실시하여야 하고, 모든 과정에서 적법절차를 엄격히 준수하여야 한다. 

제 18조 (이미지 파일의 등록)

: 정보저장매체 등에 기억된 정보를 이미지 파일로 복제한 경우에는 이를 디지털수사통합업무관리시스템에 등록한다. 

제 20조 (디지털 증거의 무결성 유지 등을 위한 조치)

: 정보저장매체 등의 봉인 해제, 이미지 파일로 복제, 디지털수사통합업무관리시스템에 등록하는 과정은 사진을 촬영하는 등 디지털 증거의 진정성, 무결성, 신뢰성 유지를 위하여 필요한 조치를 취하여야 한다.

# [메모리 포렌식]

메모리 포렌식이란?

- 컴퓨터 ****메모리 덤프에 대한 포렌식 분석 이다. 
주요 응용 분야는 컴퓨터 하드 드라이브에 데이터를 남기지 않을 만큼 은밀한 고급 컴퓨터 공격을 조사하는 것이다.
- 결과적으로 메모리를 분석하여 포렌식 정보를 얻어야 한다.

- 컴퓨터 하드웨어 중 주 기억장치(RAM)에 남아있는 데이터 흔적을 분석하는 기법이다.
- RAM 은 휘발성이 강하지만 프로세스 정보, 네트워크 연결 정보, 악성코드 파일 정보, 시스템 관련 데이터 구조, 사용자 활동 정보 등의  고유의 독특한 정보가 남아있다.

- 컴퓨터 시스템은 구조적으로 중앙처리장치(CPU, Central Processing Unit)에 의해 연산이 이루어진다.
    - 여기서 어떠한 소프트웨어라도 메모리인 RAM에 그 데이터와 코드가 적재되어야만 중앙처리장치에서 연산이 가능하기 때문이다.

- 따라서 메모리 포렌식의 주 목적은 악성코드와 관련있는 데이터를 추출하고, 어떻게, 어떤 이벤트가 발생했는지 등의 RAM 에 남아있는 악성코드 감염과 관련된 다양한 흔적을 분석하여 침해 사고 대응과 분석 과정에서 이용하는 기법이라고 말할 수 있다.

### Dump란?

- 어떤 장애가 발생했을 때
    - 프로그램의 오류 수정이나 디버그를 위해 그 상태를 외부 장치의 하나인 프린터 등 인쇄기 같은 출력 장치에 표시, 출력 혹은 인쇄 하기 위하여 기억 장치나 파일 내용의 전체 또는 일부 자료에 기억시킨 내용을 보조 기억 장치 등 기록 매체에 복사, 전이하는 조작을 일컫는다.
- 컴퓨터 주기억장치와 레지스터, 데이터나 프로그램 등 디지털 계산기에 그러한 내용이 존재 및 지정된 메모리 영역이다.

### 메모리 덤프 파일이란?

- 프로세스의 메모리를 정해진 덤프 포맷에 따라 기록한 파일이다.

- 코어 덤프(core dump)
- 메모리 덤프(memory dump) 또는 시스템 덤프(system dump)
    - 위의 덤프들은 컴퓨터 프로그램이 특정 시점에 작업 중이던 메모리 상태를 기록한 것으로, 보통 프로그램이 비정상적으로 종료했을 때 만들어진다.

- +, 추가적으로, 추가적인 검사를 위해 많은 양의 메모리 데이터를 저장하는 것을 의미한다.

# [네트워크 포렌식]

네트워크 포렌식(Network Forensics)

- 네트워크 상의 데이터 흐름을 분석하여 사이버 공격, 데이터 유출, 부정 행위 등을 탐지하고 조사하는 과정이다.
- 네트워크 포렌식은 다양한 기술과 도구를 사용하여 네트워크 트래픽을 캡처하고 분석하며, 이를 통해 이상 징후를 발견하고 사건의 원인과 경로를 파악하는 데 중요한 역할을 한다.

### 1. 네트워크 포렌식 개요

1. 네트워크란?
- 네트워크는 둘 이상의 컴퓨터와 이들을 연결하는 링크의 조합

물리적 네트워크는 네트워크를 구성하는 하드웨어(어댑터, 케이블 및 전화선과 같은 장비)이다.

- 소프트웨어 및 개념 모델이 논리적 네트워크를 형성한다.
- 다른 유형의 네트워크 및 에뮬레이터는 서로 다른 기능을 제공한다.
- 현대식 컴퓨터 네트워크의 복잡도로 인해 네트워크의 작업 방법을 설명하기 위한 여러 개념적 모델이 등장했는데,
- 그 가운데 가장 일반적인 모델 중 하나가 ISO의 개방 시스템 연결 규약(OSI) 참조 모델이다.
    - 이는 OSI 7계층 모델이라고도 한다.

### 네트워크 포렌식이란?

네트워크 포렌식은 네트워크 상에서 발생하는 모든 활동을 기록하고 분석하여 특정 사건이나 공격에 대한 증거를 수집하는 과학적 기법이다. 이는 침입 탐지 시스템(IDS)이나 침입 방지 시스템(IPS)과 밀접한 관계가 있으며, 종종 이러한 시스템과 함께 사용된다.

- 침입 방지 시스템이란?
    - 의심스러운 활동을 탐지하고 탐지 시 경고를 생성하는 모니터링 시스템이다. 이러한 경고에 따라 보안 운영 센터 분석가 또는 인시던트 대응자는 문제를 조사하고 위협을 수정하기 위한 적절한 조치를 취할 수 있다.
    
    - 분류
        - 호스트 기반
            - 호스트 기반 IDS는 특정 엔드포인트에 배포되며 내부 및 외부 위협으로부터 보호하도록 설계되었다. 이러한 IDS는 머신을 오가는 네트워크 트래픽을 모니터링하고, 실행 중인 프로세스를 관찰하고, 시스템의 로그를 검사할 수 있다. 호스트 기반 IDS의 가시성은 호스트 머신으로 제한되어 의사 결정에 사용할 수 있는 컨텍스트를 감소시키지만 호스트 컴퓨터의 내부에 대한 심층적인 가시성을 제공한다.
            
        - 네트워크 기반
            - 네트워크 기반 IDS 솔루션은 보호된 전체 네트워크를 모니터링하도록 설계되었다. 네트워크를 통해 흐르는 모든 트래픽에 대한 가시성을 가지며 패킷 메타데이터 및 내용을 기반으로 결정을 내린다. 이 더 넓은 관점은 더 많은 컨텍스트와 광범위한 위협을 탐지할 수 있는 기능을 제공한다. 그러나 이러한 시스템은 보호하는 엔드포인트의 내부에 대한 가시성이 부족하다.
            

### 네트워크 포렌식의 목적

- 사이버 공격 탐지
    - 네트워크 포렌식을 통해 사이버 공격의 발생 여부와 그 유형을 탐지한다.
    - 추가로, 사이버 공격의 종류는?
        1. 랜섬웨어
            1. 암호화를 사용하여 공격 대상이 몸값을 지불하도록 설계된 멀웨어이다. 
            2. 시스템에 존재하면 멀웨어는 사용자의 파일을 암호화하고 암호 해독 키에 대한 대가로 지불을 요구한다. 
            3. 최신 암호화 알고리즘은 사용 가능한 기술로 깨지지 않기 때문에 암호화된 파일을 복구하는 유일한 방법은 백업(사용 가능한 경우)에서 데이터를 복원하거나 무작위 수요를 지불하는 것이다.
            4. 랜섬웨어는 가장 눈에 띄고 번성하는 멀웨어 유형 중 하나가 되었으며 코로나 팬데믹은 이러한 유형의 멀웨어가 번성할 수 있는 환경을 제공했다.  
            5. 최근 몇 년 동안 일부 랜섬웨어 변종은 "이중 갈취" 공격을 수행하도록 진화했다.
            6. 메이즈(Maze), 소디노키비(Sodinokibi)/레빌(REvil), 도플페이머(DopplelPaymer), 넴티(Nemty) 및 기타 랜섬웨어 변종은 암호화하기 전에 파일 사본을 훔쳐 사용자가 몸값 지불을 거부하면 파일을 침해하겠다고 위협한다. 
            7. 이러한 추세는 2019년 말 Maze에서 시작되었지만 2020년 내내 더 많은 그룹이 이를 채택하면서 계속 성장했다.
            
        2. 멀웨어
            1. 랜섬웨어는 멀웨어의 일종이지만 유일한 유형은 아니다.
            2. 멀웨어 변종은 민감한 정보를 수집하고 훔치는 것부터 원치 않는 광고를 표시하고 감염된 시스템에 영구적인 손상을 입히는 것까지 모든 작업을 수행하도록 설계될 수 있다.
            3. 가장 일반적인 유형의 멀웨어는 다양한 유형의 공격이 공격자에게 다소 이익이 되기 때문에 해마다 다르다. 
                - 크립토마이너
                    - 피해자의 컴퓨터를 사용하여 암호화폐를 채굴하고 공격자에게 이익을 주는 멀웨어이다.
                - 모바일 멀웨어
                    - 멀웨어 타겟팅 모바일 디바이스이다. (SMS 및 소셜 미디어 앱을 악용하는 악성 애플리케이션 및 공격 포함)
                - 봇넷 멀웨어
                    - 시스템을 감염시켜 봇넷에 추가하는 멀웨어로, 봇넷 컨트롤러의 명령에 따라 사이버 공격 및 기타 불법 활동에 참여한다.
                - 인포스틸러
                    - 감염된 컴퓨터에서 민감한 정보를 수집하여 멀웨어 운영자에게 보내는 멀웨어이다.
                - 뱅킹 트로이 목마
                    - 금융 정보를 구체적으로 표적으로 삼고 뱅킹 웹 사이트 자격 증명 및 유사한 정보를 훔치려고 시도하는 멀웨어이다.
                - 랜섬웨어
                    - 사용자 컴퓨터의 파일을 암호화하고 암호 해독 키에 대한 지불을 요구하는 멀웨어이다.
                    
        3. 파일리스 공격
            1. 바이러스 백신 솔루션은 일반적으로 악성 콘텐츠의 징후가 있는지 디바이스의 각 파일을 검사하여 디바이스에서 멀웨어를 검색하려고 시도한다. 
            2. 파일리스 멀웨어는 파일을 사용하지 않음으로써 위협 탐지에 대한 이러한 접근 방식을 우회하려고 시도한다. 
            3. 대신 멀웨어는 감염된 컴퓨터에 내장된 기능에 대한 명령 집합으로 구현된다. 
                1. 이 방법으로 멀웨어가 동일한 목표를 달성할 수 있지만 일부 방어 솔루션을 검색하기가 더 어려워질 수 있다.
                2. 파일리스 멀웨어의 주요 차별화 요소는 파일이 없다는 것이다. 
                3. 기존 멀웨어와 동일한 기능을 많이 수행한다. 
                    1. 예를 들어, 20년 8월에 탐지된 파일리스 P2P(Peer-to-Peer) 봇넷 멀웨어인 FritzFrog는 시스템을 감염시키고 암호화폐를 채굴하도록 설계되었다. 
                    
        4. 피싱
            1. 피싱은 공격자가 대상 시스템에 대한 액세스 권한을 얻기 위해 사용하는 가장 일반적인 방법 중 하나이다. 
            2. 조직 네트워크의 취약점을 찾아 악용하는 것보다 사용자를 속여 악성 링크를 클릭하거나 첨부 파일을 열도록 하는 것이 더 쉬운 경우가 많다.
            3. 피싱 공격은 자격 증명 도용, 멀웨어 전달, 금융 사기, 민감한 데이터 도난 등 다양한 목표를 달성할 수 있다.
            4. 피싱은 역사적으로 사이버 공격자가 사용하기 쉽고 성공률이 높기 때문에 캠페인을 시작하는 가장 일반적인 방법이었다.
            5. 코로나 기간 동안 사이버 범죄자들이 사무실 밖에서 근무하는 직원과 바이러스에 대한 불확실성 분위기를 이용하면서 이러한 추세는 가속화되었다.
            6. 코로나는 일반적인 피싱 미끼의 영향을 증폭시켰다. 
                1. 예를 들어, 블랙 프라이데이와 사이버 먼데이는 피싱 범죄자들이 흔히 악용하는 구실이며,코로나로 인한 온라인 쇼핑의 증가로 인해 2020년에 특히 효과적이었다. 
                2. 그 결과, 블랙 프라이데이와 사이버 먼데이를 앞둔 몇 주 동안 피싱 이메일 양이 전월 초에 비해 두 배로 증가했다.
                
        5. 중간자 공격
            1. 많은 네트워크 프로토콜은 암호화를 통해 도청자로부터 보호되므로 트래픽을 읽을 수 없다. 
            2. MitM(Man-in-the-Middle) 공격은 연결을 두 조각으로 나누어 이러한 보호를 우회한다. 
            3. 공격자는 클라이언트 및 서버와 별도의 암호화된 연결을 만들어 연결을 통해 전송된 데이터를 읽고 대상으로 전달하기 전에 원하는 대로 수정할 수 있다.
            4. MitM 공격은 HTTPS와 같은 프로토콜을 사용하여 무력화할 수 있다. 
                1. 이후 모바일의 등장으로 인해 이는 더욱 위험한 공격 공간이 되었다. 
                2. 모바일 앱은 네트워크 연결과 관련하여 사용자에게 가시성을 거의 또는 전혀 제공하지 않으며 MitM 공격에 취약한 통신에 안전하지 않은 프로토콜을 사용할 수 있다.
                
        6. 악성 앱
            1. 많은 조직이 컴퓨터에 사이버 보안 노력을 집중하고 있지만 모바일 디바이스는 조직의 사이버 보안에 대한 위협이 증가하고 있다. 
            2. 점점 더 모바일 디바이스를 사용하여 업무를 수행하고 있고, 민감한 회사 데이터에 액세스함에 따라 악성 모바일 애플리케이션은 점점 더 위험해지고 있다. 
                1. 이러한 애플리케이션은 민감한 데이터 훔치기, 랜섬웨어로 파일 암호화 등 데스크톱 멀웨어가 할 수 있는 모든 작업을 수행할 수 있다.
                
        7. 서비스 거부 공격
            1. DoS(서비스 거부) 공격은 중요한 서비스에 대한 액세스를 거부하도록 설계되었다. 
            2. 애플리케이션의 취약성을 악용하거나(충돌을 유발) 시스템이 관리할 수 있는 것보다 더 많은 데이터 또는 요청으로 시스템을 플러딩(합법적인 요청을 처리할 수 없게 만듦)으로써 수행할 수 있다. 
            3. 경우에 따라 공격자는 진행 중인 공격을 중지하거나 위협적인 공격을 방지하기 위해 몸값 지불을 요구하는 랜섬 디도스 공격을 수행한다.
                1. 디도스 / 도스
                
        8. 제로데이 익스플로
            1. 소프트웨어에는 약점과 취약성이 포함되어 있으며, 이러한 취약성 중 상당수는 공격자가 잠재적으로 악용할 수 있는 프로덕션에 도달한다. 
            2. 이 프로덕션 취약성은 회사 내부, 외부 보안 연구원 또는 사이버 공격자에 의해 발견된다.

- 증거 수집
    - 법적 증거로 사용할 수 있는 데이터를 수집하고 보존한다.
- 사건 분석
    - 공격의 원인, 경로, 영향을 분석하여 대응 방안을 마련한다.
- 보안 강화
    - 네트워크 보안 취약점을 발견하고 이를 개선한다.
    

## 2. 네트워크 포렌식의 주요 기법

### 패킷 캡처(Packet Capture)

패킷 캡처는 네트워크를 통해 전송되는 모든 데이터를 수집하는 과정이다. Wireshark, tcpdump 등의 도구를 사용하여 네트워크 트래픽을 실시간으로 캡처할 수 있다. 패킷 캡처는 네트워크의 물리적 위치에서 데이터를 실시간으로 수집하거나, 네트워크 장치의 포트 미러링 기능을 이용하여 수행할 수 있다.

!다운로드.png

### 패킷 분석(Packet Analysis)

캡처한 패킷을 분석하여 데이터 흐름, 프로토콜 사용, 이상 트래픽 등을 조사한다. 패킷 분석을 통해 네트워크 상의 의심스러운 활동을 파악할 수 있다. 이는 패킷의 헤더 정보와 페이로드 내용을 분석하여 트래픽의 출처와 목적지, 전송된 데이터의 유형 등을 파악하는 과정이다.

- Wireshark

!다운로드.jpg

### 트래픽 분석(Traffic Analysis)

트래픽 분석은 네트워크 트래픽의 패턴과 양을 분석하여 이상 징후를 탐지하는 과정이다. 이는 주로 네트워크 모니터링 도구를 사용하여 수행된다. 트래픽 분석은 정상적인 네트워크 사용 패턴을 이해하고, 이를 바탕으로 비정상적인 트래픽을 탐지하는 데 중요하다.

### 로그 분석(Log Analysis)

네트워크 장치(예: 라우터, 스위치, 방화벽)와 서버의 로그 파일을 분석하여 의심스러운 활동을 찾아낸다. Splunk, ELK Stack 등의 로그 관리 도구를 사용하여 로그 데이터를 효율적으로 분석할 수 있다. 로그 분석은 각 장치에서 발생하는 이벤트를 기록하고, 이를 종합하여 네트워크 상의 이상 징후를 파악하는 데 중요하다.

### 타임라인 분석(Timeline Analysis)

네트워크 이벤트의 발생 시간을 기준으로 타임라인을 작성하여 사건의 흐름을 이해한다. 이는 사건의 원인과 경로를 파악하는 데 유용하다. 타임라인 분석은 네트워크 상의 각 활동을 시간순으로 정리하여 사건의 발생 순서와 연관성을 명확히 하는 과정이다.

### 통신 분석(Communication Analysis)

특정 호스트 간의 통신을 분석하여 불법적인 데이터 전송이나 악성 활동을 탐지한다. 이는 호스트 간의 트래픽 패턴을 분석하여, 비정상적인 통신이 발생하는지 여부를 파악하는 과정이다. 통신 분석은 네트워크 포렌식에서 매우 중요한 기법으로, 침입자나 악성 코드의 통신 행위를 탐지하는 데 사용된다.

## 3. 네트워크 포렌식 도구

1. Wireshark

Wireshark는 가장 널리 사용되는 패킷 캡처 및 분석 도구로, 네트워크 트래픽을 실시간으로 캡처하고 상세히 분석할 수 있다. Wireshark는 사용하기 쉬운 GUI를 제공하며, 다양한 프로토콜을 지원하여 상세한 패킷 분석이 가능하다. 이를 통해 네트워크 상의 다양한 활동을 시각화하고 분석할 수 있다.

- 패킷이란? → 바이러스!
    - 바이러스 또는 네트워크 바이러스는 네트워크를 통해 전송되는 형식화된 데이터 트래픽이다.
    - 네트워크 바이러스의 주요 구성요소는 사용자 데이터와 제어 정보이다.

tcpdump는 커맨드 라인 기반의 패킷 캡처 도구로, 네트워크 인터페이스에서 패킷을 캡처하여 분석할 수 있다. tcpdump는 Wireshark와 달리 GUI를 제공하지 않지만, 강력한 필터링 기능을 통해 필요한 패킷만 선택적으로 캡처할 수 있다.

1. NetworkMiner

NetworkMiner는 패킷을 캡처하여 분석하고, 호스트 정보, 파일 추출, 세션 분석 등을 수행하는 도구이다. NetworkMiner는 네트워크 트래픽을 분석하여 호스트의 운영 체제, 열린 포트, 사용 중인 서비스 등을 파악할 수 있으며, 이를 통해 네트워크 상의 각 호스트의 활동을 모니터링할 수 있다.

1. Splunk

Splunk는 로그 데이터를 수집하고 분석하는 강력한 도구로, 네트워크 포렌식에도 널리 사용된다. Splunk는 다양한 소스에서 데이터를 수집하고, 이를 실시간으로 분석하여 시각화할 수 있다. 이를 통해 네트워크 상의 이상 징후를 빠르게 탐지하고 대응할 수 있다.

1. ELK Stack

ELK Stack(Elasticsearch, Logstash, Kibana)은 로그 데이터를 수집, 저장, 시각화하는 오픈 소스 도구로, 네트워크 로그 분석에 유용하다. Elasticsearch는 데이터 검색과 분석을 담당하고, Logstash는 데이터 수집과 처리, Kibana는 데이터 시각화를 담당한다. ELK Stack은 대규모 로그 데이터를 효율적으로 관리하고 분석할 수 있다.

## 4. 네트워크 포렌식 사례

### 해킹 공격 분석

한 기업의 네트워크가 해킹 공격을 받았을 때, 네트워크 포렌식 기법을 사용하여 공격의 경로와 방법을 분석하고, 필요한 증거를 수집하여 법적 대응에 활용한 사례를 설명한다. 이를 통해 공격자가 어떤 방법으로 침입했는지, 어떤 데이터를 유출했는지, 그리고 공격의 원인을 파악할 수 있다.

### 데이터 유출 사건

데이터 유출 사건이 발생했을 때, 네트워크 포렌식을 통해 유출된 데이터의 종류, 양, 유출 경로를 파악하고, 유출을 방지하기 위한 보안 강화 방안을 마련한 사례를 소개한다. 이를 통해 데이터 유출의 원인과 피해 범위를 정확히 파악하고, 재발 방지를 위한 조치를 취할 수 있다.

## 5. 네트워크 포렌식의 법적 및 윤리적 문제

### 법적 문제

네트워크 포렌식 과정에서 수집된 데이터는 법적 증거로 사용될 수 있으므로, 데이터 수집 및 분석 과정에서 법적 절차와 규정을 준수해야 한다. 이는 개인정보 보호법, 통신비밀보호법 등 관련 법률을 포함한다. 법적 문제를 해결하기 위해서는 수집된 데이터의 무결성과 신뢰성을 유지하는 것이 중요하다.

### 윤리적 문제

네트워크 포렌식 과정에서 개인의 프라이버시가 침해될 수 있으므로, 윤리적 기준을 준수하여 필요한 최소한의 데이터만 수집하고, 수집된 데이터를 적절히 보호해야 한다. 윤리적 문제를 해결하기 위해서는 투명한 절차와 정책을 수립하고, 이를 철저히 준수하는 것이 중요하다.

## 6. 네트워크 포렌식의 미래

### 인공지능의 활용

인공지능(AI)과 머신러닝(ML) 기술을 네트워크 포렌식에 적용하여, 더 정교하고 신속한 분석이 가능해질 것이다. 예를 들어, AI 기반 이상 징후 탐지 시스템은 실시간으로 네트워크 트래픽을 분석하여 잠재적인 위협을 탐지할 수 있다. 이를 통해 보안 위협을 빠르게 식별하고 대응할 수 있다.

### 클라우드 포렌식

클라우드 환경에서의 네트워크 포렌식은 새로운 도전 과제를 제공한다. 클라우드 서비스 제공자의 협조와 데이터 접근 권한 문제가 주요 이슈로 떠오르고 있으며, 이를 해결하기 위한 새로운 기술과 기법이 개발되고 있다. 클라우드 포렌식은 클라우드 인프라의 복잡성을 다루기 위해 다양한 도구와 기술을 필요로 한다.

### IoT 포렌식

사물인터넷(IoT) 기기의 증가로 인해 네트워크 포렌식의 범위가 확대되고 있다. IoT 기기에서 발생하는 데이터를 분석하여 보안 위협을 탐지하고 대응하는 기술이 필요하다. IoT 포렌식은 다양한 기기와 프로토콜을 다루기 때문에 더 복잡한 분석 기술이 요구된다.

### 법적 및 규제 변화

네트워크 포렌식의 법적 및 규제 환경은 지속적으로 변화하고 있다. 이에 따라 최신 법적 요구 사항을 충족하고, 윤리적 기준을 준수하는 포렌식 기법이 필요하다. 법적 및 규제 변화에 따라 네트워크 포렌식 전문가들은 지속적으로 최신 정보를 습득하고 이를 적용해야 한다.

## [암호화 해제]

디지털 포렌식에서 암호화 해제는 중요한 역할을 한다. 암호화된 데이터를 복구하고 분석하는 과정에서 암호화 해제는 필수적이며, 이를 통해 법적 증거를 확보하고 사건을 해결할 수 있다. 다음은 디지털 포렌식 측면에서 암호화 해제에 관한 자세한 내용이다.

## 1. 암호화 해제의 기본 개념

### 암호화와 복호화

- 암호화(Encryption)
    - 평문 데이터를 특정 알고리즘을 사용하여 암호문으로 변환하는 과정이다. 이는 데이터의 기밀성을 유지하기 위해 수행된다.
- 복호화(Decryption)
    - 암호화된 데이터를 원래의 평문으로 되돌리는 과정이다. 이는 암호화 과정에서 사용된 키를 필요로 한다.

### 대칭키 암호화와 비대칭키 암호화

- 대칭키 암호화(Symmetric Key Encryption)
    - 동일한 키로 데이터를 암호화하고 복호화하는 방식이다. 대표적인 알고리즘으로는 AES, DES 등이 있다.
- 비대칭키 암호화(Asymmetric Key Encryption)
    - 서로 다른 키(공개키와 비밀키)를 사용하여 데이터를 암호화하고 복호화하는 방식이다. 대표적인 알고리즘으로는 RSA, ECC 등이 있다.
    

## 2. 암호화 해제 기법

### 2키 추측 공격(Key Guessing Attack)

- 무차별 대입 공격(Brute Force Attack)
    - 가능한 모든 키를 대입하여 암호문을 복호화해 보는 방법이다. 키 공간이 크면 시간이 많이 걸린다.
- 사전 공격(Dictionary Attack)
    - 미리 준비된 키 목록(사전)을 사용하여 암호문을 복호화해 보는 방법이다. 사전에 있는 키로만 시도하기 때문에 무차별 대입 공격보다 빠르다.

### 암호 알고리즘 분석

- 암호 해독(Cryptanalysis)
    - 암호화 알고리즘의 구조적 약점을 분석하여 키를 찾아내는 방법이다. 대표적인 기법으로는 차분 공격(Differential Cryptanalysis), 선형 공격(Linear Cryptanalysis) 등이 있다.
- 측면 채널 공격(Side-Channel Attack)
    - 암호화 과정에서 발생하는 물리적 특성(전력 소비, 전자기 방사 등)을 분석하여 키를 추출하는 방법이다.

### 소프트웨어 취약점 이용

- 취약점 공격(Vulnerability Exploitation)
    - 암호화 소프트웨어나 프로토콜의 취약점을 이용하여 암호화된 데이터를 해제하는 방법이다. 예를 들어, SSL/TLS 프로토콜의 취약점을 이용한 POODLE 공격이 있다.

## 3. 암호화 해제 도구

### 무차별 대입 공격 도구

- John the Ripper
    - 다양한 해시 함수와 암호 알고리즘을 대상으로 무차별 대입 공격을 수행하는 도구이다.
- Hashcat
    - GPU를 이용하여 빠르게 무차별 대입 공격을 수행할 수 있는 도구이다.

### 암호 분석 도구

- Cain and Abel
    - 네트워크 트래픽 분석, 무차별 대입 공격, 사전 공격, 암호 해독 등 다양한 기능을 제공하는 도구이다.
- Aircrack-ng
    - 무선 네트워크(Wi-Fi) 암호화를 해제하는 데 사용되는 도구이다.

### SW 취약점 이용 도구

- Metasploit: 다양한 소프트웨어 취약점을 이용한 공격 모듈을 제공하는 도구로, 암호화 소프트웨어의 취약점을 이용한 공격을 수행할 수 있다.
- Burp Suite: 웹 애플리케이션의 보안 취약점을 분석하고 공격하는 데 사용되는 도구로, 암호화된 통신의 취약점을 이용할 수 있다.

## 4. 암호화 해제의 법적 및 윤리적 문제

### 법적 문제

암호화 해제는 데이터의 기밀성을 침해할 수 있기 때문에 법적 절차와 규정을 준수해야 한다. 불법적인 암호화 해제는 개인 정보 보호법, 통신비밀보호법 등을 위반할 수 있다. 디지털 포렌식 전문가들은 법적 허가를 받은 경우에만 암호화 해제를 시도해야 한다.

### 윤리적 문제

암호화 해제는 개인의 프라이버시와 데이터 보호의 측면에서 윤리적인 문제를 발생시킬 수 있다. 합법적인 수사 목적 외에는 암호화 해제를 시도하지 않아야 하며, 필요할 경우 최소한의 데이터만 접근하도록 해야 한다. 윤리적 기준을 준수하는 것이 중요하다.

## 5. 암호화 해제의 실제 사례

### 범죄 수사 상에서의 활용범위

법 집행 기관은 범죄 수사를 위해 암호화된 데이터의 해제를 시도할 수 있다. 예를 들어, 테러리스트의 스마트폰에서 데이터를 추출하여 범죄 조직의 활동을 파악하는 경우가 있다. 이러한 사례에서 암호화 해제는 결정적인 증거를 확보하는 데 중요한 역할을 한다.

### 데이터 복구

데이터 복구 전문가는 손상된 하드 드라이브나 암호화된 파일에서 데이터를 복구하기 위해 암호화 해제를 시도할 수 있다. 이는 중요한 데이터를 되찾기 위한 필수 과정이 될 수 있다. 예를 들어, 랜섬웨어 공격으로 암호화된 데이터를 복구하기 위해 암호화 해제를 시도할 수 있다.

## 6. 암호화 해제의 미래

### 양자 컴퓨팅의 등장

양자 컴퓨터는 기존의 컴퓨터보다 훨씬 빠르게 암호화된 데이터를 해제할 수 있는 잠재력을 가지고 있다. 이는 대칭키 암호화와 비대칭키 암호화 모두에 큰 영향을 미칠 수 있다. 양자 컴퓨팅 시대에는 기존 암호화 알고리즘의 안전성이 크게 감소할 것으로 예상된다.

### 인공지능과 머신러닝의 활용

인공지능(AI)과 머신러닝(ML) 기술을 암호화 해제에 적용하면, 더 정교하고 효율적인 암호화 해제 기법이 개발될 수 있다. AI와 ML은 암호화 알고리즘의 패턴을 분석하고, 키 추출 과정을 자동화하는 데 활용될 수 있다.

## [로그 분석]

디지털 포렌식에서 로그 분석(Log Analysis)은 매우 중요한 과정이다. 로그는 시스템, 네트워크 장비, 애플리케이션 등에서 발생하는 다양한 이벤트를 기록한 데이터로, 로그 분석을 통해 시스템 내에서 발생한 활동을 추적하고 이상 징후를 발견하며, 범죄 증거를 수집할 수 있다.

## 1. 로그의 개념과 종류

### 로그

로그는 시스템, 네트워크 장치, 애플리케이션 등이 작동하면서 발생하는 이벤트를 시간 순서대로 기록한 파일이다. 로그 파일은 시스템의 상태, 오류, 사용자 활동 등을 기록하여, 문제 발생 시 원인 파악과 해결을 돕는다.

### 로그의 종류

- 시스템 로그(System Log)
    - 운영 체제와 관련된 이벤트를 기록한다. 예를 들어, 사용자 로그인/로그아웃, 시스템 부팅/종료, 오류 메시지 등이 포함된다.
    
- 애플리케이션 로그(Application Log)
    - 특정 애플리케이션의 이벤트를 기록한다. 예를 들어, 데이터베이스 접속, 애플리케이션 오류, 사용자 활동 등이 포함된다.
    
- 보안 로그(Security Log)
    - 보안 관련 이벤트를 기록한다. 예를 들어, 로그인 시도, 권한 변경, 방화벽 활동 등이 포함된다.
    
- 네트워크 로그(Network Log)
    - 네트워크 장치(라우터, 스위치, 방화벽 등)의 이벤트를 기록한다. 예를 들어, 트래픽 흐름, 연결 시도, 네트워크 오류 등이 포함된다.
    
- 웹 서버 로그(Web Server Log)
    - 웹 서버에서 발생하는 이벤트를 기록한다. 예를 들어, HTTP 요청/응답, 사용자 접속 정보, 오류 메시지 등이 포함된다.
    

## 2. 로그 분석의 중요성

### 사건 재구성

로그 분석을 통해 시스템이나 네트워크에서 발생한 사건을 시간 순서대로 재구성할 수 있다. 이는 사건의 발생 원인과 경로를 파악하는 데 중요한 역할을 한다.

### 이상 징후 탐지

로그 데이터를 분석하여 평상시와 다른 이상 징후를 탐지할 수 있다. 예를 들어, 갑작스러운 트래픽 증가, 비정상적인 로그인 시도 등이 있을 때 이를 빠르게 탐지할 수 있다.

### 법적 증거 수집

로그 파일은 법적 증거로 사용할 수 있는 중요한 데이터다. 로그 분석을 통해 침입 경로, 공격 방법, 피해 범위 등을 파악하고, 이를 법적 절차에서 증거로 활용할 수 있다.

### 시스템 및 네트워크 보안 강화

로그 분석을 통해 보안 취약점을 발견하고, 이를 개선하여 시스템과 네트워크의 보안을 강화할 수 있다. 예를 들어, 자주 발생하는 보안 이벤트를 분석하여 예방 조치를 취할 수 있다.

## 3. 로그 분석의 주요 기법

### 패턴 분석

로그 데이터에서 특정 패턴을 식별하여 이상 징후를 탐지한다. 예를 들어, 연속된 로그인 실패 시도를 분석하여 무차별 대입 공격을 탐지할 수 있다.

### 타임라인 분석

로그 데이터를 시간 순서대로 정렬하여 사건의 흐름을 파악한다. 이는 사건이 발생한 시간대와 그 전후의 활동을 분석하는 데 유용하다.

### 상관 관계 분석

다양한 로그 소스에서 발생한 이벤트 간의 상관 관계를 분석한다. 예를 들어, 네트워크 로그와 시스템 로그를 비교하여 특정 공격이 어떤 경로로 이루어졌는지 파악할 수 있다.

### 통계 분석

로그 데이터를 통계적으로 분석하여 평상시와 다른 이상 징후를 탐지한다. 예를 들어, 특정 시간대에 트래픽이 비정상적으로 증가한 경우 이를 분석하여 원인을 파악할 수 있다.

### 머신러닝 및 인공지능 기법

머신러닝과 인공지능 기법을 사용하여 로그 데이터를 자동으로 분석하고 이상 징후를 탐지할 수 있다. 이는 대량의 로그 데이터를 효율적으로 처리하고, 더 정교한 분석을 가능하게 한다.

## 4. 로그 분석 도구

### Splunk

Splunk는 로그 데이터를 수집, 저장, 분석, 시각화하는 데 사용되는 강력한 도구다. 다양한 소스에서 로그 데이터를 수집하고, 이를 실시간으로 분석하여 이상 징후를 탐지할 수 있다.

### ELK Stack

ELK Stack(Elasticsearch, Logstash, Kibana)은 로그 데이터를 수집, 저장, 시각화하는 오픈 소스 도구다. Logstash는 로그 데이터를 수집하고 처리하며, Elasticsearch는 데이터를 저장하고 검색하며, Kibana는 데이터를 시각화한다.

### Graylog

Graylog는 실시간 로그 수집, 저장, 분석을 위한 오픈 소스 도구다. 다양한 소스에서 로그 데이터를 수집하고, 이를 효율적으로 분석하여 이상 징후를 탐지할 수 있다.

### OSSEC

OSSEC는 호스트 기반 침입 탐지 시스템(HIDS)으로, 로그 분석을 통해 시스템의 이상 징후를 탐지한다. OSSEC는 다양한 운영 체제와 애플리케이션을 지원하며, 실시간으로 로그 데이터를 분석한다.

## 5. 로그 분석의 실제 사례

### 침입 탐지

로그 분석을 통해 시스템에 대한 무단 침입을 탐지할 수 있다. 예를 들어, 보안 로그에서 비정상적인 로그인 시도나 권한 상승 시도를 분석하여 침입을 탐지하고 대응할 수 있다.

### 데이터 유출 감지

로그 분석을 통해 데이터 유출을 감지할 수 있다. 예를 들어, 네트워크 로그에서 대량의 데이터 전송을 탐지하여 데이터 유출 시도를 파악하고 대응할 수 있다.

### 내부자 위협 탐지

로그 분석을 통해 내부자의 악의적인 활동을 탐지할 수 있다. 예를 들어, 시스템 로그와 애플리케이션 로그를 분석하여 내부자의 비정상적인 데이터 접근이나 조작을 파악할 수 있다.

## 6. 로그 분석의 법적 및 윤리적 문제

### 법적 문제

로그 데이터는 법적 증거로 사용될 수 있기 때문에, 로그 수집과 분석 과정에서 법적 절차와 규정을 준수해야 한다. 불법적인 로그 수집은 개인정보 보호법, 통신비밀보호법 등을 위반할 수 있다.

### 윤리적 문제

로그 분석은 개인의 프라이버시를 침해할 수 있으므로, 윤리적 기준을 준수하여 필요한 최소한의 데이터만 수집하고, 수집된 데이터를 적절히 보호해야 한다. 로그 분석 과정에서 개인 정보나 민감한 데이터를 다룰 때는 특별한 주의가 필요하다.

## 7. 로그 분석의 미래

### 인공지능과 머신러닝의 활용

인공지능(AI)과 머신러닝(ML) 기술을 로그 분석에 적용하여 더 정교하고 효율적인 분석이 가능해질 것이다. AI와 ML은 로그 데이터에서 패턴을 학습하고, 이를 바탕으로 이상 징후를 자동으로 탐지할 수 있다.

### 빅데이터 분석 기술의 발전

로그 데이터는 대규모로 생성되기 때문에 빅데이터 분석 기술이 로그 분석에 중요한 역할을 할 것이다. 빅데이터 기술을 활용하면 대량의 로그 데이터를 효율적으로 처리하고 분석할 수 있다.

### 클라우드 기반 로그 분석

클라우드 환경에서의 로그 분석은 새로운 도전 과제를 제공한다. 클라우드 서비스 제공자의 협조와 데이터 접근 권한 문제가 주요 이슈로 떠오르고 있으며, 이를 해결하기 위한 새로운 기술과 기법이 개발되고 있다.

## [모바일 포렌식]

디지털 포렌식의 하위 유형인 모바일 포렌식은 전자 소스에서 데이터를 검색하는 것과 관련이 있다. 

스마트폰 및 태블릿과 동일한 모바일 기기에서 증거를 복구하는 것이 모바일 포렌식의 중심이다. 

개인이 데이터 전송, 수신자 및 검색의 대부분의 모바일 기기에 의존하기 때문에 이러한 기기가 응답할 수 있는 무제한의 증거를 보관하고 유지하는 것이 합리적으로 지켜야 할 사항이다.

모바일 기기는 기록, 문자 메시지, 온라인 검색 기록, 위치 데이터와 관련된 광범위한 전화 정보를 수정할 수 있다. 

우리는 종종 모바일 포렌식 법률 기구와 연관만, 모바일 장치에서 얻은 증거에 의존할 수 있는 사람은 모바일 포렌식 뿐만 아니라 법률 기구 기관뿐이 아니다.

모바일 포렌식은 법정 절차와 민사 또는 형사 수사에서 전제를 뒷받침하거나 이의를 제기하기 위해 전자적으로 저장된 정보를 수집하고 분석하는 프로세스이다. 

모바일 기기의 확산과 이들이 보유한 데이터 양으로 인해 모바일 포렌식은 디지털 포렌식 조사자에게 없어서는 안 될 리소스가 되었다.

그러나 이 방대한 데이터를 사용하여 무결성을 손상시키지 않고 진실을 파헤치려면 증거를 매우 신중하게 다루고 처리해야 한.

모바일 기기에서 어떤 종류의 정보를 추출할 수 있고, 어떤 가능성이 있을까?

- 미디어
    
    일반적인 미디어 유형에는 비디오, 사진, 오디오가 있습니다. 모바일 기기는 미디어를 생성하고 수신할 수 있다. 
    
    모바일 기기는 카메라와 마이크를 사용하여 미디어를 생성하는 동시에 인터넷이나 다양한 다른 소스를 통해 미디어를 수신할 수 있다.
    
    많은 앱은 휴대폰의 다른 모든 앱에서 액세스할 수 있는 방식으로 미디어를 저장한다. 
    
    반면, 일부 앱은 독점 형식이나 암호화된 형태로 미디어를 저장할 수 있다.
    
- 통화 기록
    
    통화 기록 정보는 기기에서 발신 및 수신한 통화의 연락처 정보, 시간 및 기간을 보여준다. 
    
    사용자는 기기에 통화 녹음 앱을 설치할 수도 있다. 
    
    이 경우 당사자 간의 대화는 저장된 오디오 파일을 통해 액세스할 수도 있다.
    
- 메시지
    
    다양한 메시징 앱이 있으며, 거의 모든 유형의 파일을 첨부 파일로 보내고 받을 수 있다. 
    
    메시지를 찾을 때는 사전 설치된 앱과 사용자가 설치한 앱을 모두 분석하고 관련 증거를 수집해야 한다.
    
- 연락처
    
    모든 모바일에는 연락처를 저장하기 위한 하나 이상의 사전 설치된 앱이 있지만, 사용자가 설치한 앱은 자체 연락처 데이터베이스를 유지할 수 있다. 
    
    연락처를 분석하면 유용한 정보를 얻을 수 있다.
    
- 브라우징 데이터
    
    웹 브라우저는 방문한 웹사이트에 대한 많은 정보를 저장한다. 
    
    웹 주소와 미디어, 그리고 많은 경우 웹사이트의 로그인 정보를 저장한다.
    
- 업무 관리 앱
    
    일정 항목, 할 일 목록, 메모 등도 조사자에게 유용한 정보를 제공할 수 있다.
    
    - 범죄자의 하루 일과..?
    
- 위치 데이터
    
    거의 모든 최신 스마트폰과 태블릿 기기에는 GPS가 내장되어 있으며, 사용자 설정에 따라 많은 앱이 이 데이터를 기록하고 있을 수 있다. 
    
    앱을 조사하면 허용 시간에 기기의 시간과 위치를 올바르게 식별할 수 있다. 
    
    GPS 외에도 기기는 연결된 Wi-Fi 네트워크와 휴대전화 타워를 기반으로 위치 데이터를 저장한다.
    
- 기타 데이터
    
    기타 유용한 데이터에는 다른 앱, 워드 프로세서 또는 스프레드시트에서 생성된 데이터가 포함될 수 있다. 
    
    유용한 데이터는 시스템 파일과 로그에서도 찾을 수 있다.
    
    이는 가장 일반적인 데이터 유형의 예이지만, 그 외에도 많은 데이터 유형이 있다. 
    
    각 모바일 포렌식 사건에 따라 고유한 데이터 유형을 기준으로 하고, 해당 사건과 가장 관련성이 높은 데이터를 찾아야 한다.
    

### 모바일 포렌식 메뉴얼

- 압수 및 격리
    
    디지털 포렌식에 대한 증거는 법원에서 적절하게 보관, 분석 및 수용되어야 한다. 
    
    모바일 기기 압수에는 수많은 어려움이 있다. 
    
    모바일 포렌식 방법의 이 단계와 관련된 두 가지 주요 사항은 잠긴 활성화 및 네트워크/셀룰러 연결이다.
    
- 신분
    
    신분 목적은 모바일 개체에서 정보를 검색하는 것이다. 
    
    적절한 PIN, 형식 또는 형식으로 녹음을 사용하면 잠긴 화면에 표시될 수 있다. 
    
    앱, 사진, SMS등은 모두 비슷한 잠금 기능을 가질 수 있습니다. 반면에 장비는 소프트웨어 및/또는 하드웨어 수준에서 털리기 힘든 보안성을 제공해준다. 
    
- 수집
    
    데이터 유닛이 이동 가능하기 때문에 모바일로 데이터를 제어하는 것은 불가능하다. 
    
    회사에서 메시지나 데이터를 전송하게 되는 제어 기능이 추가되었다. 
    
    다양한 평행 기술의 겨울에 데이터를 저장할 수 있다는 점에도 불구하고, 데이터 저장될 수 있다. 
    
    - 예를 들어 장치와 앱 확인 데이터 동기화는 직접 또는 클라우드를 통해 수행할 수 있다.
    - 모바일 기기에서는 일반적으로 Apple의 iCloud, Microsoft의 One Drive와 같은 서비스를 활용하므로 데이터 수집 가능성이 노출될 수 있다.
    - 실제로 조사 자료를 모바일에서 원격으로 수집하여 귀하가 초월할 수 있다는 신호를 주의 깊게 관찰해야 한다.
    
- 조사 및 분석
    
    모바일 은 암데이터 전송이 가능하기 때문에 추적이 매우 어렵다. 
    
    인터넷의 메시지나 데이터를 이동하자마자 제어권을 넘긴다. 
    
    수많은 동료들과 함께 겨울에 위치를 알 수 있다는 점에도 불구하고, 데이터 저장될 수 있다.
    

- 보고
    
    물리적 및 전자적 증거의 압수, 보관, 통제, 이전, 분석 및 분석 도구 또는 서류 추적을 법의학으로 보고라고 한다. 
    
    모든 유형의 증거가 어떻게 수집, 추적 및 보호되는지에 대한 검증이 이루어지는 프로세스이다.
    

### 모바일 포렌식 역사 (짧게)

연구 분야로서 모바일 기기의 법의학적 검사는 1990년대 후반과 2000년대 초반에 시작되었다. 

범죄에서 모바일 폰의 역할은 법 집행 기관에서 오랫동안 인식되어 왔다. 

소비자 시장에서 이러한 기기의 가용성이 증가하고 지원하는 통신 플랫폼(예: 이메일, 웹 브라우징)이 더 다양해지면서 법의학적 검사에 대한 수요가 증가했다.

모바일 기기를 조사하기 위한 초기 노력은 최초의 컴퓨터 포렌식 조사와 유사한 기술을 사용했다. 

즉, 화면을 통해 직접 휴대전화 콘텐츠를 분석하고 중요한 콘텐츠를 사진으로 찍었다. 

그러나 이는 시간이 많이 걸리는 프로세스로 판명되었고 모바일 기기의 수가 증가하기 시작하면서 조사관은 보다 효율적인 데이터 추출 수단을 요구했다. 

진취적인 모바일 포렌식 조사관은 때때로 휴대전화 또는 PDA 동기화 소프트웨어를 사용하여 이미징을 위해 장치 데이터를 포렌식 컴퓨터에 "백업"하거나, 때로는 데이터가 동기화된 의심되는 컴퓨터의 하드 드라이브에서 컴퓨터 포렌식을 수행하기도 했다. 

그러나 이러한 유형의 소프트웨어는 휴대전화에 쓸 수 있을 뿐만 아니라 읽을 수도 있었고 삭제된 데이터는 검색할 수 없었다.

일부 법의학 검사관은 OEM이 디버깅이나 업데이트를 위해 휴대폰 메모리를 "플래시"하기 위해 개발한 도구인 "플래셔" 또는 "트위스터" 상자를 사용하여 삭제된 데이터도 검색할 수 있다는 것을 발견했다. 

그러나 플래셔 상자는 침습적이며 데이터를 변경할 수 있다. 

사용하기 복잡할 수 있으며 법의학 도구로 개발되지 않았기 때문에 해시 검증도 수행하지 않고(대부분의 경우) 감사 추적도 수행하지 않는다. 

따라서 물리적 법의학 검사의 경우 더 나은 대안이 여전히 필요하다.

이러한 요구 사항을 충족하기 위해, 최소한의 방해로 전화 메모리를 복구하고 별도로 분석할 수 있는 상업용 도구가 등장했다.

시간이 지남에 따라 이러한 상업용 기술은 더욱 발전했고, 일부 전문 도구를 사용하면 독점적인 모바일 기기에서 삭제된 데이터를 복구하는 것이 가능해졌다. 

게다가 상업용 도구는 추출 프로세스의 대부분을 자동화하여 현재 컴퓨터에 비해 모바일 기기를 소지한 용의자를 만날 가능성이 훨씬 더 높은 최소한의 훈련을 받은 응급 대응자도 분류 및 데이터 미리보기 목적으로 기본 추출을 수행할 수 있게 되었다.

### 법의학적 과정

모바일 기기에 대한 포렌식 프로세스는 다른 디지털 포렌식 분야와 대체로 일치하지만, 몇 가지 특별한 우려 사항이 적용된다. 

일반적으로 프로세스는 압수, 취득, 검사/분석의 세 가지 주요 범주로 나눌 수 있다. 

섭취, 검증, 문서화/보고, 보관과 같은 컴퓨터 포렌식 프로세스의 다른 측면은 여전히 적용된다. 

모바일 기기를 압수하는 것은 다른 디지털 미디어와 동일한 법적 고려 사항의 적용을 받는다. 

모바일 기기는 종종 켜진 상태로 회수된다. 

압수의 목적은 증거를 보존하는 것이므로 종료를 피하기 위해 기기를 동일한 상태로 운반하여 파일이 변경되는 경우가 많다. 

또한 조사관이나 응급 대응자는 사용자 잠금이 활성화될 위험이 있다.

휴대전화를 켜 두면 다른 위험이 따른다. 

기기가 여전히 네트워크/셀룰러 연결을 할 수 있기 때문이다.  

이렇게 하면 새로운 데이터가 유입되어 증거가 덮어쓰일 수 있다. 

연결을 방지하기 위해 모바일 기기는 종종 가방 안에서 운반 및 검사된다. 

그렇더라도 이 방법에는 두 가지 단점이 있다. 

첫째, 대부분의 가방은 터치스크린이나 키패드를 사용할 수 없기 때문에 기기를 사용할 수 없다. 

그러나 투명한 유리와 특수 장갑을 낀 상태에서 기기를 사용할 수 있는 특수 케이지를 구입할 수 있다. 

이 옵션의 장점은 네트워크 연결을 차단하는 동안 다른 포렌식 장비에 연결할 수 있고 기기를 충전할 수 있다는 것이다. 

이 옵션을 사용할 수 없는 경우 기기를 비행기 모드로 전환하거나 심(SIM) 카드를 복제하여 네트워크 격리를 하는 것이 좋다. 

### 모바일 포렌식 수집

법의학 프로세스의 두 번째 단계는 수집이다. 

이 경우 일반적으로 장치에서 자료를 검색하는 것을 말한다(컴퓨터 법의학에서 사용되는 비트 복사 이미징과 비교).

모바일의 독점적 특성으로 인해 전원이 꺼진 상태에서는 데이터를 수집할 수 없는 경우가 많다. 

대부분의 모바일 기기 수집은 라이브로 수행된다. 

고급 메모리 관리를 사용하는 보다 진보된 스마트폰의 경우 충전기에 연결하고 패러데이 케이지에 넣는 것은 좋은 관행이 아닐 수 있다. 

모바일 기기는 네트워크 연결 해제를 인식하고 따라서 메모리 관리자가 데이터를 쓰도록 트리거할 수 있는 상태 정보를 변경한다. 

대부분의 모바일 기기용 데이터 수집 도구는 상업적 성격을 띠고 있으며, 종종 자동화된 하드웨어와 소프트웨어 구성 요소로 구성된다.

### 모바일 분석

점점 더 많은 모바일 기기가 컴퓨터의 파일 시스템과 유사한 고급 파일 시스템을 사용함에 따라 하드 디스크 포렌식에서 방법과 도구를 인계받거나 약간의 변경만 필요할 수 있다.

FAT 파일 시스템은 일반적으로 NAND 메모리에서 사용된다. 

차이점은 사용되는 블록 크기로, 하드디스크의 경우 512바이트 보다 크고 사용되는 메모리 유형에 따라 달라진다.

다양한 소프트웨어 도구가 메모리 이미지에서 데이터를 추출할 수 있다. 

파일 헤더의 특성을 검색하기 위해 전문적이고 자동화된 포렌식 소프트웨어 제품이나 16진수 편집기와 같은 일반 파일 뷰어를 사용할 수 있다. 

16진수 편집기의 장점은 메모리 관리에 대한 보다 깊은 통찰력이지만 16진수 편집기를 사용하면 많은 수작업과 파일 시스템 및 파일 헤더 지식이 필요하다. 

반면, 전문 포렌식 소프트웨어는 검색을 간소화하고 데이터를 추출하지만 모든 것을 찾지 못할 수 있다.

# [멀웨어 포렌식]

### 멀웨어 포렌식의 주요 단계와 도구

### 1. 초기 탐지

멀웨어 포렌식의 첫 단계는 악성 활동의 초기 징후를 감지하는 것이다. 이는 다음과 같은 도구를 사용하여 수행할 수 있다:

- **IDS/IPS**
    - 침입 탐지 시스템(Intrusion Detection System)과 침입 방지 시스템(Intrusion Prevention System)을 사용하여 비정상적인 네트워크 트래픽을 모니터링한다.
- **SIEM**
    - 보안 정보 및 이벤트 관리(Security Information and Event Management) 시스템을 통해 로그와 이벤트를 분석하여 의심스러운 활동을 식별한다.

멀웨어 포렌식의 초기 탐지 단계는 매우 중요한 과정으로, 악성 활동의 초기 징후를 감지하고 적절한 대응 조치를 취하는 데 핵심적인 역할을 한다. 초기 탐지 단계에서는 다양한 도구와 기법을 활용하여 잠재적인 위협을 신속하게 식별할 수 있다.

네트워크 트래픽 모니터링

네트워크 트래픽 모니터링은 초기 탐지의 핵심 요소 중 하나이다. 이를 통해 비정상적인 트래픽 패턴을 식별하고, 잠재적인 멀웨어 활동을 탐지할 수 있다.

- **Wireshark**
    - 네트워크 패킷을 캡처하고 분석하여 의심스러운 트래픽을 식별하는 데 사용된다.
- **Bro/Zeek**
    - 네트워크 분석 프레임워크로, 실시간 트래픽을 모니터링하고 이상 활동을 탐지한다.

시스템 로그 분석

시스템 로그는 다양한 이벤트와 활동을 기록하므로, 로그 분석을 통해 멀웨어 활동의 징후를 감지할 수 있다.

- **SIEM**
    - Security Information and Event Management 시스템을 사용하여 다양한 로그 소스를 통합하고 분석한다. Splunk, IBM QRadar, ArcSight 등이 대표적인 SIEM 도구이다.
- **OSSEC**
    - 호스트 기반 침입 탐지 시스템으로, 실시간 로그 분석 및 경고 기능을 제공한다.

파일 무결성 검사

파일 무결성 검사는 시스템 파일의 무결성을 주기적으로 확인하여 멀웨어에 의해 변경된 파일을 탐지한다.

- **Tripwire**
    - 파일 무결성 모니터링 도구로, 파일 시스템 변화를 추적하고 알림을 제공한다.

- **AIDE**
    - Advanced Intrusion Detection Environment는 오픈 소스 파일 무결성 검사 도구로, 시스템 파일의 무결성을 확인한다.

행위 기반 탐지

행위 기반 탐지는 멀웨어의 행동 패턴을 분석하여 비정상적인 활동을 감지하는 방법이다.

- **Cylance**
    - 머신러닝 기반의 보안 솔루션으로, 파일의 행동을 분석하여 멀웨어를 탐지한다.
- **Cuckoo Sandbox**
    - 멀웨어를 안전한 환경에서 실행하여 그 행동을 분석하고, 비정상적인 활동을 식별한다.

휴리스틱 분석

휴리스틱 분석은 알려지지 않은 멀웨어를 탐지하기 위해 파일의 특성과 행동 패턴을 분석하는 기법이다.

- **Malwarebytes**
    - 멀웨어 탐지 도구로, 휴리스틱 분석을 통해 알려지지 않은 멀웨어를 식별한다.
- **ESET NOD32**
    - 휴리스틱 분석을 포함한 다양한 탐지 기법을 사용하여 멀웨어를 탐지한다.

예외 활동 모니터링

시스템 및 네트워크에서의 예외 활동을 모니터링하여 비정상적인 행위를 탐지한다.

- **Sysmon**
    - 시스템 모니터링 도구로, 윈도우 시스템의 고급 로그를 수집하여 분석한다.
- **EventSentry**
    - 네트워크와 시스템에서의 다양한 이벤트를 모니터링하고, 예외 활동을 탐지한다.

이 밖에도 다양한 도구와 기법을 통해 멀웨어 포렌식의 초기 탐지 단계를 효과적으로 수행할 수 있다는 점..!  

초기 탐지가 성공적으로 이루어지면, 멀웨어의 유입을 신속하게 차단하고 추가적인 분석을 통해 정확한 대응 방안을 마련할 수 있다.

### 2. 증거 수집

멀웨어 포렌식의 두 번째 단계는 악성 소프트웨어의 샘플을 수집하는 것이다. 이는 다음과 같은 도구를 사용하여 수행할 수 있다.

- **FTK Imager**
    - 디스크 이미징 도구로, 하드 디스크와 메모리의 이미지를 생성하여 원본 데이터를 보존한다.

!화면 캡처 2024-07-17 195633.png

- **Wireshark**
    - 네트워크 트래픽 분석 도구로, 네트워크 패킷을 캡처하고 분석하여 악성 통신을 식별한다.
    

멀웨어 포렌식의 증거 수집 단계는 초기 탐지 이후 가장 중요한 단계 중 하나로, 정확하고 철저하게 수행해야 한다. 이 단계에서 수집된 증거는 후속 분석과 법적 절차에서 핵심적인 역할을 하므로, 원본 데이터를 보존하고 변조되지 않도록 하는 것이 중요하다. 다음은 증거 수집 단계에서 사용하는 다양한 도구와 기법을 더 자세히 설명한 내용이다.

디스크 이미징

디스크 이미징은 하드 드라이브나 기타 저장 장치의 전체 이미지를 생성하여 원본 데이터를 변경하지 않고 복사하는 과정이다.

- **FTK Imager**: 법적 효력이 있는 디스크 이미지를 생성하는 도구로, 파일 시스템의 모든 데이터를 정확하게 복제한다.
- **dd**: 유닉스 계열 시스템에서 널리 사용되는 저수준의 디스크 이미징 도구로, 원본 데이터의 정확한 복사를 가능하게 한다.
- **EnCase**: 디지털 포렌식 도구로, 디스크 이미징뿐만 아니라 다양한 분석 기능을 제공한다.

메모리 덤프

메모리 덤프는 시스템의 물리적 메모리(RAM) 내용을 캡처하여 분석하는 과정이다. 이는 실행 중인 악성 프로세스와 그 관련 데이터를 추출하는 데 유용하다.

- **Volatility**: 오픈 소스 메모리 포렌식 프레임워크로, 메모리 덤프를 분석하여 악성 활동을 식별할 수 있다.
- **FTK Imager**: 메모리 덤프 기능도 제공하여, 메모리 데이터를 캡처하고 분석할 수 있다.
- **Belkasoft RAM Capturer**: 가볍고 사용하기 쉬운 메모리 덤프 도구로, 실시간 메모리 캡처를 지원한다.

네트워크 패킷 캡처

네트워크 패킷 캡처는 네트워크를 통해 주고받는 데이터를 수집하여 분석하는 과정이다. 이는 멀웨어의 통신 패턴을 파악하고, C2 서버와의 연결을 식별하는 데 유용하다.

- **Wireshark**: 네트워크 프로토콜 분석기로, 네트워크 패킷을 캡처하고 분석하는 데 널리 사용된다.
- **tcpdump**: 명령줄 기반의 네트워크 패킷 캡처 도구로, 실시간 패킷 데이터를 수집하고 저장할 수 있다.
- **Network Miner**: 네트워크 포렌식 분석 도구로, 패킷 캡처 데이터를 시각화하고 분석하는 데 유용하다.

로그 수집

시스템 및 애플리케이션 로그는 멀웨어 활동을 추적하는 중요한 증거를 제공한다. 다양한 로그 소스를 통합하여 분석하는 것이 중요하다.

- **Splunk**: 실시간 로그 수집 및 분석 도구로, 다양한 로그 소스를 통합하여 이상 활동을 식별할 수 있다.
- **Graylog**: 오픈 소스 로그 관리 도구로, 중앙 집중식 로그 수집 및 분석 기능을 제공한다.
- **LogRhythm**: 보안 인텔리전스 및 로그 관리 플랫폼으로, 실시간 로그 모니터링 및 분석을 지원한다.

파일 및 레지스트리 수집

멀웨어가 생성하거나 수정한 파일 및 레지스트리 키를 수집하는 것은 중요한 증거를 제공한다.

- **FTK Imager**: 파일 시스템에서 특정 파일이나 폴더를 추출할 수 있다.
- **Regshot**: 윈도우 레지스트리 상태를 비교하여, 멀웨어가 변경한 레지스트리 키를 추적한다.
- **Autoruns**: 윈도우 시스템의 자동 실행 항목을 분석하여, 멀웨어가 시스템 시작 시 자동으로 실행되도록 설정한 항목을 식별한다.

이메일 및 메시지 수집

멀웨어가 이메일을 통해 전파된 경우, 관련 이메일 데이터를 수집하는 것이 중요하다.

- **MailXaminer**: 이메일 분석 및 포렌식 도구로, 다양한 이메일 포맷을 지원하며 이메일 내용을 분석할 수 있다.
- **AccessData Email Examiner**: 이메일 메시지와 첨부 파일을 분석하여, 멀웨어 전파 경로를 추적할 수 있다.

### 3. 정적 분석

정적 분석 단계에서는 멀웨어 샘플을 실행하지 않고 분석한다. 주요 도구는 다음과 같다:

- **IDA Pro**
    - 정적 디스어셈블리 도구로, 바이너리 코드를 분석하여 멀웨어의 구조와 기능을 파악한다.
- **PEiD**
    - 실행 파일의 패킹 여부를 검사하고, 패킹된 파일을 식별한다.

1. 파일 메타데이터 분석

멀웨어 파일의 메타데이터를 조사하여 파일의 속성과 특성을 파악한다.

- **파일 해시 계산**
    - MD5, SHA-1, SHA-256 등의 해시 값을 계산하여 파일의 고유 식별자를 생성한다.
- **파일 속성 확인**
    - 파일 생성 날짜, 수정 날짜, 크기 등의 속성을 확인한다.

2. 파일 헤더 분석

파일 헤더를 분석하여 파일 형식과 구조를 파악한다.

- **PE 헤더 분석**
    - 윈도우 실행 파일(PE 파일)의 헤더를 분석하여 파일의 진입점, 섹션 정보, 임포트/엑스포트 테이블 등을 확인한다.
    
    !다운로드 (1).png.png)
    
    - 헤더와 바디로 구성된다.
    - 헤더
        - 구조체 형식
    - 바디
        - 파일의 실제 코드, 데이터, 리소스 등 존재
- **ELF 헤더 분석**
    - 리눅스 실행 파일(ELF 파일)의 헤더를 분석하여 파일의 구조와 섹션 정보를 파악한다.

3. 코드 디스어셈블리

멀웨어의 바이너리 코드를 어셈블리 코드로 변환하여 분석한다.

- **IDA Pro**
    - 정적 디스어셈블리 도구로, 바이너리 코드를 어셈블리 코드로 변환하여 분석한다. 함수 호출 그래프와 코드 플로우를 시각화할 수 있다.
- **Ghidra**
    - NSA에서 개발한 오픈 소스 리버스 엔지니어링 도구로, 디스어셈블리와 디컴파일 기능을 제공한다.

4. 문자열 추출

멀웨어 파일 내에 포함된 문자열을 추출하여 유용한 정보를 얻는다.

- **Strings**
    - 파일 내에 포함된 가독성 있는 문자열을 추출하는 도구로, 명령줄 인터페이스를 통해 사용된다.
- **BinText**
    - 파일 내의 문자열을 시각화하여 표시하는 GUI 기반 도구이다.

5. 패킹 및 압축 확인

멀웨어 파일이 패킹되거나 압축되었는지 확인하여 분석의 난이도를 평가한다.

- **PEiD**
    - 윈도우 실행 파일이 패킹되었는지 여부를 검사하고, 사용된 패커의 종류를 식별한다.
- **UPX**
    - 패킹된 파일을 압축 해제하여 원래의 코드를 복원할 수 있는 도구이다.

6. 디지털 서명 검토

파일의 디지털 서명을 확인하여 파일의 신뢰성을 평가한다.

- **Sigcheck**
    - 파일의 디지털 서명을 확인하고 서명 정보를 분석하는 도구로, 명령줄 인터페이스를 통해 사용된다.
- **Sysinternals Suite**
    - 다양한 시스템 유틸리티 모음으로, Sigcheck를 포함한 여러 유용한 도구들을 제공한다.

7. 파일 비교 및 분석

유사한 멀웨어 샘플과 비교하여 변종 여부를 파악한다.

- **Binary Diffing**
    - 두 바이너리 파일을 비교하여 차이점을 식별하는 기법으로, BinDiff와 같은 도구를 사용하여 수행할 수 있다.
- **Malware Analysis Report Comparison**
    - 이전 분석된 멀웨어 보고서와 비교하여 유사한 패턴이나 코드를 식별한다.

정적 분석 단계는 멀웨어의 내부 구조와 동작을 이해하는 데 중요한 정보를 제공한다. 이러한 정보를 바탕으로 동적 분석 단계에서 보다 구체적인 행동 패턴을 파악할 수 있으며, 멀웨어의 제거와 대응 방안을 마련하는 데 큰 도움이 된다.

### 4. 동적 분석

동적 분석 단계에서는 멀웨어를 격리된 환경에서 실행하여 그 행동을 관찰한다. 주요 도구는 다음과 같다:

- **Cuckoo Sandbox**
    - 멀웨어 분석을 위한 샌드박스 환경을 제공하여 멀웨어의 행동을 기록하고 분석한다.
- **Process Monitor**
    - 시스템에서 실행 중인 프로세스를 모니터링하여 멀웨어가 생성하는 파일, 변경하는 레지스트리 키 등을 확인한다.

1. 안전한 분석 환경 설정

멀웨어를 분석하기 위한 안전한 환경을 설정하는 것이 중요하다. 이를 위해 가상화 기술을 주로 사용한다.

- **VirtualBox**
    - 가상 머신을 설정하고 멀웨어를 안전하게 실행할 수 있는 환경을 제공한다.
- **VMware**
    - 가상화 솔루션으로, 분석 환경을 설정하고 멀웨어를 격리된 상태에서 실행할 수 있다.
- **Cuckoo Sandbox**
    - 멀웨어 분석을 위한 자동화된 샌드박스 환경을 제공하며, 다양한 분석 결과를 시각화한다.

2. 프로세스 모니터링

멀웨어 실행 중에 생성되는 프로세스와 그 동작을 모니터링한다.

- **Process Monitor (ProcMon)**
    - 실시간 파일 시스템, 레지스트리, 프로세스 및 네트워크 활동을 모니터링하는 도구로, 멀웨어의 행동을 자세히 추적할 수 있다.
- **Process Explorer**
    - 실행 중인 모든 프로세스를 상세하게 보여주고, 각 프로세스의 자원 사용 현황을 모니터링한다.

3. 파일 시스템 활동 추적

멀웨어가 생성, 수정, 삭제하는 파일 및 디렉토리를 추적한다.

- **File Monitor**
    - 파일 시스템의 변화를 실시간으로 모니터링하여, 멀웨어가 파일을 어떻게 조작하는지 분석할 수 있다.
- **Sysinternals Suite**
    - 파일 시스템 활동을 모니터링할 수 있는 다양한 도구를 제공한다.

4. 네트워크 활동 분석

멀웨어가 네트워크를 통해 외부와 통신하는 패턴을 분석한다.

- **Wireshark**
    - 네트워크 트래픽을 캡처하고 분석하여 멀웨어가 외부 서버와 통신하는 방식을 파악할 수 있다.
- **Fiddler**
    - HTTP/HTTPS 트래픽을 모니터링하고 디버깅할 수 있는 도구로, 멀웨어의 웹 기반 통신을 분석한다.

5. 레지스트리 활동 모니터링

멀웨어가 레지스트리를 조작하는 활동을 추적한다.

- **Regshot**
    - 레지스트리의 상태를 비교하여 멀웨어가 변경한 항목을 확인할 수 있다.
- **Autoruns**
    - 시스템의 자동 실행 항목을 분석하여 멀웨어가 시스템 시작 시 자동으로 실행되도록 설정한 항목을 식별한다.

6. 메모리 분석

실행 중인 멀웨어의 메모리 상태를 분석하여, 메모리에 상주하는 악성 코드를 식별한다.

- **Volatility**
    - 메모리 포렌식 도구로, 메모리 덤프를 분석하여 악성 프로세스와 관련 데이터를 추출한다.
- **RAM Capturer**
    - 메모리 덤프를 캡처하여, 멀웨어의 메모리 활동을 분석할 수 있다.

7. API 호출 분석

멀웨어가 사용하는 API 호출을 모니터링하여, 그 동작 방식을 파악한다.

- **API Monitor**
    - 실행 중인 애플리케이션의 API 호출을 모니터링하고 분석할 수 있다.
- **x64dbg**
    - 디버거로, 멀웨어가 호출하는 API를 추적하여 코드의 동작을 분석한다.

### 1. 클라우드 컴퓨팅

클라우드 컴퓨팅은 인터넷을 통해 서버, 저장소, 데이터베이스, 네트워크, 소프트웨어 등의 컴퓨팅 자원을 제공하는 모델이다.

클라우드 컴퓨팅은 IT 리소스를 인터넷을 통해 온디맨드로 제공하고 사용한 만큼만 비용을 지불하는 것을 말하며

물리적 데이터 센터와 서버를 구입, 소유 및 유지 관리하는 대신, Amazon Web Services(AWS)와 같은 클라우드 공급자로부터 필요에 따라 컴퓨팅 파워, 스토리지, 데이터베이스와 같은 기술 서비스에 액세스할 수 있는 기술이다.

클라우드 서비스 모델

클라우드 서비스는 크게 세 가지 모델로 분류된다:

- **IaaS(인프라 서비스)**
    - 인프라를 서비스로 제공하는 모델로, 사용자에게 가상 서버, 저장소, 네트워크 등을 제공한다. 예시로는 Amazon Web Services(AWS), Microsoft Azure의 Virtual Machines가 있다.
    
- **PaaS(플랫폼 서비스)**
    - 플랫폼을 서비스로 제공하는 모델로, 개발자들이 애플리케이션을 개발하고 배포할 수 있는 환경을 제공한다. 예시로는 Google App Engine, AWS Elastic Beanstalk가 있다.
    
- **SaaS(소프트웨어 서비스)**
    - 소프트웨어를 서비스로 제공하는 모델로, 사용자가 애플리케이션을 인터넷을 통해 이용할 수 있게 한다. 예시로는 Google Workspace, Microsoft Office 365가 있다.
    

클라우드 배포 모델

클라우드 배포 모델은 클라우드 인프라가 어디에 위치하고 어떻게 관리되는지에 따라 구분된다:

- **퍼블릭 클라우드**
    - 다수의 사용자와 조직이 공유하는 클라우드 환경이다. 비용 효율성이 높고, 확장성이 뛰어나다.
    
- **프라이빗 클라우드**
    - 특정 조직만을 위해 구축된 클라우드 환경으로, 보안과 제어가 뛰어나지만 비용이 높을 수 있다.
    
- **하이브리드 클라우드**
    - 퍼블릭 클라우드와 프라이빗 클라우드를 결합한 모델로, 데이터와 애플리케이션을 양쪽에 분산시켜 사용하는 유연성을 제공한다.
    
    클라우드 컴퓨팅 (자세하게!)
    
    클라우드 컴퓨팅은 인터넷을 통해 컴퓨팅 자원을 제공하는 기술로, 현대 IT 환경에서 중요한 역할을 하고 있다. 이 기술은 데이터 저장소, 서버, 데이터베이스, 네트워크, 소프트웨어 등 다양한 자원을 제공하여, 사용자와 기업이 필요에 따라 자원을 활용할 수 있게 한다.
    
    클라우드 컴퓨팅은요..
    
    클라우드 컴퓨팅은 인터넷 기반 컴퓨팅의 일종으로, 물리적 서버나 데이터센터의 자원을 가상화하여 사용자에게 제공하는 것을 의미한다. 이 기술은 사용자가 필요할 때 필요한 만큼 자원을 사용하고, 사용한 만큼만 비용을 지불하는 유연한 모델을 제공한다.
    
    클라우드 서비스
    
    1. IaaS(Infrastructure as a Service)
    
    IaaS는 기본 인프라(서버, 스토리지, 네트워크)를 서비스로 제공하는 모델이다. 사용자는 가상 머신을 생성하고 관리하며, 필요에 따라 자원을 확장하거나 축소할 수 있다. 예시로는 AWS EC2, Microsoft Azure Virtual Machines, Google Compute Engine 등이 있다.
    
    2. PaaS(Platform as a Service)
    
    PaaS는 애플리케이션 개발 및 배포를 위한 플랫폼을 제공하는 서비스 모델이다. 개발자는 인프라 관리에 신경 쓰지 않고, 애플리케이션 개발에만 집중할 수 있다. 예시로는 Google App Engine, AWS Elastic Beanstalk, Microsoft Azure App Services 등이 있다.
    
    3. SaaS(Software as a Service)
    
    SaaS는 소프트웨어 애플리케이션을 서비스로 제공하는 모델이다. 사용자는 인터넷을 통해 애플리케이션에 접근하고 사용할 수 있으며, 소프트웨어 설치나 유지보수에 대한 부담이 없다. 예시로는 Google Workspace, Microsoft Office 365, Salesforce 등이 있다.
    
    4. 클라우드 배포 모델
    
    클라우드 컴퓨팅은 클라우드 인프라의 위치와 관리 방식에 따라 세 가지 배포 모델로 나뉜다
    
    1. 퍼블릭 클라우드(Public Cloud)
    
    퍼블릭 클라우드는 다수의 사용자가 공유하는 클라우드 환경이다. 클라우드 서비스 제공자가 인프라를 소유하고 운영하며, 사용자에게 서비스 형태로 제공한다. 퍼블릭 클라우드는 비용 효율성과 확장성이 뛰어나지만, 보안 및 프라이버시 이슈가 있을 수 있다.
    
    1. 프라이빗 클라우드(Private Cloud)
    
    프라이빗 클라우드는 특정 조직만을 위해 구축된 클라우드 환경이다. 조직 내부 또는 제3자 데이터센터에서 인프라를 운영하며, 높은 보안성과 제어가 가능하다. 그러나 퍼블릭 클라우드보다 비용이 높고, 관리가 복잡할 수 있다.
    
    1. 하이브리드 클라우드(Hybrid Cloud)
    
    하이브리드 클라우드는 퍼블릭 클라우드와 프라이빗 클라우드를 결합한 모델이다. 데이터와 애플리케이션을 양쪽에 분산시켜 사용하는 유연성을 제공하며, 보안이 중요한 데이터는 프라이빗 클라우드에, 비용 효율성이 중요한 애플리케이션은 퍼블릭 클라우드에 배포할 수 있다.
    
    5. 클라우드 컴퓨팅의 장단점
    
    클라우드 컴퓨팅은 여러 가지 장점과 단점을 가지고 있다. 이를 이해하면 클라우드 컴퓨팅을 효과적으로 활용할 수 있다.
    
    장점
    
    - **비용 절감**
        - 사용한 만큼만 비용을 지불하는 유연한 비용 구조로, 초기 투자 비용을 줄일 수 있다.
    - **확장성**
        - 필요에 따라 자원을 쉽게 확장하거나 축소할 수 있어, 변화하는 비즈니스 요구에 대응할 수 있다.
    - **유연성**
        - 다양한 클라우드 서비스와 애플리케이션을 쉽게 통합하고 사용할 수 있다.
    - **접근성**
        - 인터넷을 통해 어디서나 클라우드 자원에 접근할 수 있어, 원격 근무와 협업이 용이하다.
    - **관리 용이성**
        - 인프라 관리와 유지보수를 클라우드 제공자가 담당하므로, 사용자는 애플리케이션 개발과 비즈니스에 집중할 수 있다.
    
    단점
    
    - **보안 문제**
        - 클라우드 환경에서는 데이터가 외부에 저장되므로, 보안과 프라이버시 문제가 발생할 수 있다.
    - **의존성**
        - 클라우드 서비스 제공자에 대한 의존성이 커지며, 서비스 장애나 데이터 접근 제한 등의 문제가 발생할 수 있다.
    - **비용 예측 어려움**
        - 사용량에 따라 비용이 변동되므로, 정확한 비용 예측이 어렵다.
    - **데이터 전송 속도**
        - 대용량 데이터를 클라우드로 전송하는 데 시간이 걸릴 수 있다.
    
    클라우드 컴퓨팅의 보안 이슈
    
    클라우드 컴퓨팅에서의 보안은 중요한 문제이다. 클라우드 환경에서 데이터를 보호하기 위해 다양한 보안 이슈를 이해하고 대처해야 한다.
    
    데이터 보안
    
    클라우드 환경에서는 데이터가 외부 서버에 저장되므로, 데이터 암호화와 접근 제어가 중요하다. 데이터 암호화를 통해 데이터 전송 및 저장 시 보안을 강화하고, 접근 제어를 통해 권한이 없는 사용자가 데이터에 접근하지 못하도록 해야 한다.
    
    네트워크 보안
    
    클라우드 환경에서의 네트워크 보안은 중요한 이슈이다. 네트워크 트래픽을 모니터링하고, 방화벽과 침입 탐지 시스템을 통해 네트워크를 보호해야 한다. 또한, 가상 사설망(VPN)을 사용하여 안전한 네트워크 연결을 제공할 수 있다.
    
    사용자 인증 및 권한 관리
    
    클라우드 환경에서는 사용자 인증과 권한 관리가 필수적이다. 다단계 인증(MFA)을 통해 사용자 인증을 강화하고, 역할 기반 접근 제어(RBAC)를 통해 사용자 권한을 세분화하여 관리할 수 있다.
    
    규정 준수
    
    클라우드 환경에서의 규정 준수는 법적 요구 사항을 충족하기 위해 중요하다. 각국의 데이터 보호법과 산업 규제를 준수해야 하며, 이를 위해 클라우드 제공자가 제공하는 규정 준수 도구와 서비스를 활용할 수 있다.
    
    7. 클라우드 컴퓨팅의 주요 제공자
    
    클라우드 컴퓨팅 시장에는 여러 주요 제공자가 있다. 이들은 다양한 클라우드 서비스를 제공하며, 각각의 특징과 장점을 가지고 있다.
    
    Amazon Web Services(AWS)
    
    AWS는 클라우드 컴퓨팅 시장의 선도자로, 다양한 클라우드 서비스를 제공한다. EC2, S3, RDS, Lambda 등 다양한 서비스가 있으며, 전 세계에 걸쳐 데이터 센터를 운영한다. AWS는 높은 확장성과 안정성을 제공하며, 다양한 산업 분야에서 사용된다.
    
    Microsoft Azure
    
    Microsoft Azure는 Microsoft의 클라우드 플랫폼으로, IaaS, PaaS, SaaS 서비스를 제공한다. Azure는 Microsoft 제품과의 통합이 뛰어나며, 기업 환경에서 많이 사용된다. Azure Active Directory, Azure DevOps, Azure Kubernetes Service 등 다양한 서비스가 있다.
    
    Google Cloud Platform(GCP)
    
    GCP는 Google의 클라우드 플랫폼으로, 빅데이터와 머신러닝에 강점을 가지고 있다. BigQuery, TensorFlow, Kubernetes 등 다양한 서비스를 제공하며, 고성능 컴퓨팅 환경을 제공한다. GCP는 Google의 인프라와 네트워크를 활용하여 높은 성능과 안정성을 제공한다.
    
    클라우드 컴퓨팅의 미래
    
    클라우드 컴퓨팅은 계속해서 발전하고 있으며, 향후 더욱 중요한 역할을 할 것이다. 
    
    1. 엣지 컴퓨팅
    
    엣지 컴퓨팅은 데이터 처리와 분석을 중앙 클라우드 대신 데이터 발생 지점에서 수행하는 기술이다. 이는 데이터 전송 지연을 줄이고, 실시간 처리가 필요한 애플리케이션에 유용하다. 엣지 컴퓨팅과 클라우드 컴퓨팅의 결합은 다양한 산업 분야에서 새로운 가능성을 열어줄 것이다.
    
    1. 인공지능(AI)과 머신러닝
    
    클라우드 컴퓨팅은 AI와 머신러닝 기술의 발전을 가속화할 것이다. 클라우드 제공자는 AI와 머신러닝을 위한 플랫폼과 도구를 제공하여, 기업과 개발자가 손쉽게 AI 모델을 개발하고 배포할 수 있게 한다. 이는 의료, 금융, 제조 등 다양한 분야에서 혁신을 가져올 것이다.
    
    1. 하이브리드 및 멀티 클라우드 전략
    
    많은 기업들이 하이브리드 클라우드와 멀티 클라우드 전략을 채택하고 있다. 이는 퍼블릭 클라우드와 프라이빗 클라우드를 결합하거나, 여러 클라우드 제공자의 서비스를 함께 사용하는 방식이다. 이를 통해 비용 효율성과 유연성을 높이고, 비즈니스 연속성을 보장할 수 있다.
    

### 2. 클라우드 포렌식의 주요 내용

데이터 위치

클라우드 환경에서는 데이터가 전 세계 여러 데이터 센터에 분산되어 저장된다. 이는 특정 데이터의 물리적 위치를 추적하고 접근하는 것을 어렵게 한다.

접근 권한

클라우드 제공자와 사용자 간의 책임 분담 모델(Shared Responsibility Model)로 인해 증거 수집에 필요한 접근 권한을 확보하는 것이 어려울 수 있다. 클라우드 제공자가 제공하는 데이터와 로그에 대한 접근 권한을 사전에 명확히 정의하는 것이 중요하다.

데이터 보존

클라우드 환경에서는 데이터의 생성, 수정, 삭제가 매우 빠르게 이루어지므로, 필요한 증거를 신속히 보존하는 것이 중요하다. 데이터의 무결성을 유지하기 위한 절차를 마련해야 한다.

로그 수집

클라우드 서비스 제공자는 보안 및 프라이버시 문제로 인해 로그 접근을 제한할 수 있다. 따라서, 사고 발생 시 필요한 로그 데이터를 확보하는 것이 어려울 수 있다. 클라우드 환경에서 로그 수집 방법과 절차를 미리 파악해 두는 것이 중요하다.

### 3. 증거 수집 및 보존

클라우드 포렌식에서 증거 수집과 보존은 매우 중요하다. 올바른 절차를 통해 증거의 무결성과 신뢰성을 유지해야 한다.

### 1. 증거 수집

### 클라우드 환경에서의 데이터 수집 방법

1. **API 호출**:
    - 클라우드 서비스 제공자(API)들은 다양한 API를 통해 데이터에 접근할 수 있는 방법을 제공한다. AWS의 CloudTrail, Azure의 Activity Logs, GCP의 Stackdriver Logging 등을 활용해 로그 데이터를 수집할 수 있다.
    - API를 사용하여 가상 머신의 상태, 저장소 데이터, 네트워크 트래픽 등을 수집할 수 있다.
2. **가상 머신 스냅샷**:
    - 가상 머신의 상태를 캡처하여 스냅샷을 생성하면 디스크 이미지와 메모리 덤프를 포함한 데이터를 확보할 수 있다.
    - 스냅샷을 통해 당시의 시스템 상태를 그대로 복제하여 증거로 활용할 수 있다.
3. **로그 데이터**:
    - 클라우드 환경에서 발생하는 모든 활동은 로그로 기록된다. 이 로그는 중요한 증거 자료가 될 수 있다.
    - 접근 로그, 시스템 로그, 애플리케이션 로그 등 다양한 로그 데이터를 수집하여 분석할 수 있다.
4. **네트워크 트래픽**:
    - 네트워크 트래픽 데이터를 캡처하여 분석하면 데이터 유출, 비정상적인 트래픽 패턴 등을 파악할 수 있다.
    - 클라우드 제공자의 네트워크 모니터링 도구를 활용하여 네트워크 트래픽 데이터를 수집한다.
5. **스토리지 데이터**:
    - 클라우드 스토리지에서 데이터를 수집하는 방법으로, S3 버킷, Blob 스토리지 등의 데이터를 다운로드하여 증거로 보관할 수 있다.
    - 파일 메타데이터, 접근 기록 등을 포함한 스토리지 데이터를 확보한다.

### 데이터 수집 시 고려 사항

1. **무결성 보장**:
    - 수집한 데이터의 무결성을 보장하기 위해 해시 값을 사용하여 데이터 변경 여부를 확인한다.
    - 원본 데이터는 변경하지 않고, 복제본을 생성하여 분석에 활용한다.
2. **법적 준수**:
    - 데이터 수집 시 각국의 법률과 규정을 준수해야 한다. 특히 개인정보 보호법, 데이터 보호 규정 등을 철저히 따르는 것이 중요하다.
    - 법적 요구 사항을 충족하기 위해 필요한 절차와 문서를 준비한다.
3. **접근 권한**:
    - 데이터 수집을 위해 필요한 접근 권한을 확보해야 한다. 클라우드 서비스 제공자와 협력하여 필요한 권한을 얻는다.
    - 불법적인 접근을 방지하고, 승인된 인원만이 데이터에 접근할 수 있도록 관리한다.

### 2. 증거 보존

### 데이터 보존 방법

1. **데이터 암호화**:
    - 수집한 데이터를 암호화하여 보관한다. 이는 데이터 유출 시에도 무단 접근을 방지할 수 있다.
    - 암호화 키 관리도 중요하며, 안전한 장소에 키를 보관한다.
2. **해시 값 생성**:
    - 데이터의 무결성을 확인하기 위해 수집한 데이터의 해시 값을 생성하고, 이를 기록해 둔다.
    - 데이터 분석 전후의 해시 값을 비교하여 데이터 변조 여부를 확인한다.
3. **원본 데이터 보존**:
    - 원본 데이터는 변경되지 않도록 안전한 장소에 보관한다. 복제본을 생성하여 분석에 활용하며, 원본 데이터는 증거로 보존한다.
    - 원본 데이터의 보존 장소와 접근 권한을 철저히 관리한다.
4. **체인 오브 커스터디**:
    - 데이터의 수집, 전송, 보관 과정에서 체인 오브 커스터디(Chain of Custody)를 유지하여 증거의 신뢰성을 보장한다.
    - 모든 단계에서 데이터 접근자, 변경 사항 등을 기록하여 데이터의 출처와 이동 과정을 명확히 한다.

### 데이터 보존 시 고려해야 할 것

1. **보존 기간**:
    - 법적 요구 사항과 조사 목적에 따라 데이터 보존 기간을 설정한다. 일부 데이터는 사건 해결 후에도 장기 보존이 필요할 수 있다.
    - 데이터 보존 기간이 끝나면 적절한 절차에 따라 데이터를 안전하게 삭제한다.
2. **보안 관리**:
    - 보존된 데이터는 물리적, 논리적 보안 조치를 통해 보호한다. 데이터 센터의 접근 통제, 네트워크 보안, 데이터 암호화 등을 철저히 관리한다.
    - 정기적인 보안 점검과 감사 절차를 통해 데이터 보안 상태를 유지한다.
3. **규정 준수**:
    - 데이터 보존과 관련된 법적 요구 사항을 철저히 준수한다. 각국의 데이터 보호법, 산업 규제 등을 준수하며, 필요한 절차와 문서를 준비한다.
    - 규정 준수를 위한 교육과 훈련을 통해 모든 관련 인원이 규정을 이해하고 따를 수 있도록 한다.
